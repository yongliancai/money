# 07｜跨平台持久化：不依賴對話記憶

## 核心原則
跨 AI 平台的可靠承載物是**專案內版本化的規範與可執行檢查**。平台記憶、Rules、Skills 和專屬指令只是把它們載入上下文的適配器。不能假定任何 AI 閱讀一次就永久記住。

## 平台能力偵測

1. 辨識 Agent 與目前版本；若不確定，查詢可用工具/官方設定，不猜測。
2. 檢查是否支援專案指令、Rules、Skills、持久化設定、倉庫級約束、自動載入順序。
3. 實際確認哪些檔案會被自動讀入、作用範圍、衝突時的優先序，以及是否有長度限制。
4. 不支援持久化時，保留 `PROJECT-ENGINEERING.md` 類通用文件及入口指令，要求每次明確載入。

## 單一來源與平台適配

- 建議在專案內維護一份**主要工程規範**（名稱由專案自行決定）及其引用的驗證命令、架構圖與決策紀錄。
- 平台專屬入口只負責指向主要規範及任務相關檔案，不要長篇複製成互相矛盾的版本。
- 可依支援狀態使用 `AGENTS.md`、`CLAUDE.md`、Cursor 專案 Rules、Skills 或其他等價機制；**名稱僅為候選，不代表所有平台或版本均會自動讀取**。
- 不要把密鑰、個資、執行中暫存資訊或未經確認的推測寫入長期記憶。

## 驗收方法

1. 在目前環境確認規範可被載入。
2. 啟動**全新、沒有原對話上下文**的工作階段（若平台允許），交付同一專案。
3. 要求新 Agent 指出規範入口、禁止操作、驗證命令、部署批准規則。
4. 讓新 Agent 在隔離情境辨識一項故意違規的變更，且實際檢查必須攔截。
5. 若平台無法驗證新工作階段，標記為 `BLOCKED`；不得宣稱跨對話成功。

## 變更治理
專案規範有版本、責任人/變更原因、審查紀錄和例外期限。平台適配檔變更時應檢查仍與主要規範一致。
