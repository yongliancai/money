# 示範決策案例（非固定安裝清單）

## 案例 A：純 HTML/CSS/JS 小網站
- 現象：修改一個元件常影響其他頁面排版。
- 先查：是否已有可重現的頁面或視覺比較方式，是否有共用 CSS 命名衝突。
- 候選：CSS 命名規約、少量關鍵頁面截圖比較、Playwright smoke test；不需要直接導入 TLA+。
- 驗收：故意移除關鍵按鈕應使測試失敗，正常頁面操作通過。

## 案例 B：Node.js API + 聊天模型
- 現象：聊天模型偶爾偏離指定文件回答。
- 先查：檢索資料、Prompt 版本、模型設定、工具輸出及失敗對話是否可重現。
- 候選：文件引用驗證、拒答案例、固定評測集、Schema、API 整合測試。
- 驗收：多組文件內、文件外、模糊提問案例各有量測結果；不可把偶然一次成功當作全面保證。

## 案例 C：Electron main/renderer
- 現象：renderer 直接 import main 模組，權限/打包出錯。
- 候選：清楚的目錄與 IPC 邊界；依賴圖規則；非法引用的負例檢查。
- 驗收：違規依賴被攔截，合法跨程序通訊可通過整合測試。

## 案例 D：跨裝置通知狀態同步
- 現象：訊息重送、離線及重連時狀態不一致。
- 候選：狀態圖、property-based/state-machine test；若風險高且有模型能力，評估 TLA+。
- 驗收：定義不變量，檢查競爭條件與重試情境。模型正確不保證實作零缺陷，仍需系統測試。
